## What is State in React?

A huge part of React is writing components, and we usually want the interactive components to undergo visual changes as a result of interactions. To achieve this, we need components to remember things about themselves between renders. This is where state becomes useful. State is a component's memory.

## The useState() hook

`useState()` is an essential built-in hook in React, and it allows you to define state in a functional component. To use `useState()`, you first need to import it from React:

```ts
import { useState } from "react";
```

`useState()` accepts an initial value as a parameter, and returns an array with two elements: the current state value, and a function to update the state value. 

```javascript
const [stateValue, setStateValue] = useState(initialValue);
```

The initialValue is only used on the first mount, unless you remount the component. State updates schedule a re-render, meaning when you call the setter function (`setStateValue()` in this example), React applies the update in the next component render. Until the component is re-rendered, the state variable stays the old value. 

Adding more state variables is as easy as adding more `useState()` calls. 

## How State works in React

When state or props change, React **re-renders** the component: it runs your function again from the top and uses the latest state from `useState()` to figure out what the UI should look like. React builds a description of the next UI and reconciles it with the previous render’s description before touching the DOM. It then updates the real DOM only where needed (this matching step is often called reconciliation). You do not manage that diff yourself. Calling the setter is enough to schedule the next render.

## How to Structure State

Managing and structuring state are crucial if you want to avoid bugs. In general, don't put values in state that can be calculated using existing values, state, or props. There are some key rules to keep in mind: 

Don't Mutate State. Primitives are already immutable, but if you are using reference-type values like arrays or objects, never mutate them as it can lead to unpredictable results. For example, mutating one of these objects does not guarantee the page is re-rendered because the state reference looks unchanged, but creating a new object and using this instead does.

To change state, you should use the setter function. If you are using an array or object as a value for your state, then you must first create a new array/value from the old one, and set state with this instead of mutating the existing array/object. I included the example from [The Odin Project](https://www.theodinproject.com/lessons/node-path-react-new-more-on-state) below as it is a great example. 

```JavaScript
// Don't do this
const handleIncreaseAge = () => {
  // mutating the current state object
  person.age = person.age + 1;
  setPerson(person);
};

// Do this instead
const handleIncreaseAge = () => {
  // copy the existing person object into a new object
  // while updating the age property
  const newPerson = { ...person, age: person.age + 1 };
  setPerson(newPerson);
};
```

## Local UI State

In many cases, you can house a component's state locally (inside the component itself). This is useful when the component only cares about itself. 

Let's use the `ThemeMenu` component in this site as an example. Only this component cares whether the menu is open or not, so we can place `useState()` inside the component. This is called colocation, meaning state lives next to the UI that uses it.

```TypeScript
export function ThemeMenu() {
  const [open, setOpen] = useState(false);
...
```

Later in the render section of the component, we can create a button, and set its event handler to call `setOpen()` as the functional updater, allowing us to open or close the menu:

```TypeScript
  return (
    <div className="theme-menu">
      <button
        type="button"
        className={`theme-menu-toggle theme-menu-toggle--dark`}
        aria-label="Color theme"
        aria-expanded={open}
        aria-haspopup="menu"
        aria-controls="theme-menu"
        onClick={() => setOpen((v) => !v)}  // Event handler
      >
...
```

## Lifting State

There are also cases when one component needs to access another component's state. The light/dark theme on this website is another good example for this. While the `ThemeMenu` dropdown lets users pick their theme preference from "Light", "Dark", and "System", every UI component on the website needs to read this preference to display the right CSS. 

So how can we achieve this? We need to move state from a child to a common ancestor so that more than one component can read or update it. So while the `open` state can live locally on the `ThemeMenu` component, the `preference` state used to store theme preference has to be lifted to an ancestor of all components that need to change when the user selects a theme:

```tsx
// Parent owns the state
function App() {
  // We create the state with the initial "system" state. 
  // The available states are: "light", "dark", and "system".
  const [preference, setPreference] = useState("system");  
  return <ThemeMenu preference={preference} onChange={setPreference} />;
}

// Child does not own it — it receives value + updater
function ThemeMenu({ preference, onChange }) {
  return <button onClick={() => onChange("dark")}>Dark</button>;
}
```

This is called lifting state up. We are essentially lifting state from the child `ThemeMenu` component to the ancestor, `App`, and controlling the menu through props passed down from `App`. 

In this site, we also used context, but I will leave this for a future blog post about `useContext()`. 

## Controlled inputs

Form inputs are a common `useState` use case. When you pass the state into `value` and update it from `onChange`, React controls what the field shows—this is a **controlled input**.

```tsx
const [draftQuery, setDraftQuery] = useState("");

<input
  value={draftQuery}
  onChange={(e) => setDraftQuery(e.target.value)}
/>
```

On this site’s blog search, that local string is intentionally a draft: the URL’s q param is what actually filters posts, and we copy the draft into the URL after the user pauses typing. The important useState idea is the same: state holds what the input displays. 

## Conclusion

`useState()` is an essential built-in function that holds the values of elements you render. Use it whenever the UI needs to remember something that can change—menu open state, form text, a loading flag after a fetch, and so on. Components can either have their own local state, or if many components need to access the state, it can be lifted to a mutual ancestor.
